## 1. Language and conformance

MUST/MUST NOT are unconditional requirements/prohibitions. SHOULD/SHOULD NOT are recommendations; any departure MUST be recorded with its reason and MUST NOT change a MUST requirement. MAY is optional permission. Sections 2-18 and the expected results in section 19 are normative. Section 20 is an informative, evidence-bounded mapping review; section 21 is the readiness decision. Protocol notes never grant support by themselves.

Two implementations MUST give the same validation, selection, retry and outcome decisions given the same ordered input events, time, registry snapshot and explicit descriptor/policy values. Different physical targets or policies are different inputs. Undeclared policy defaults MUST NOT be invented. Every supported operation MUST have a complete descriptor satisfying this specification; unknown external guarantees MUST remain UNKNOWN, not be inferred from a protocol name.

Records below list required fields unless suffixed `?`. Optional means absent, not an implicit default. `[]` is an ordered list, `map<K,V>` has unique keys, and `union` is explicitly tagged. Records are closed: unknown argument fields MUST be rejected. Optional additive observation fields MAY be retained diagnostically without interpretation; unknown operation IDs MUST be rejected. No schema here mandates JSON, UUID, storage technology or network transport.

Type shorthand is normative: `Version` aliases `common_model_version`; bare identifier field names inherit their section 2 OpaqueId or semantic-name type and scope; bare counter names inherit scoped UInt64 revisions/generations. `Record` means the exact closed Schema RECORD declared for that argument, not an untyped map. Bare reachability/authorization fields inherit the Binding enums; keys referencing named records inherit those record types. A `Unit = {path:String[], unit:NONE/NORMALIZED/MS/COUNT/CHANNEL_NUMBER/REFERENCE/TEXT}` identifies an exact schema path (empty path means the whole value); duplicate paths and unresolved paths are invalid. No alias creates a new identity namespace.

## 2. Identifiers, versions and generations

`OpaqueId` is 1-128 ASCII characters from `[A-Za-z0-9._:-]`; it is case-sensitive and MUST be compared by exact bytes. Lexicographic comparison means unsigned ASCII byte order. IDs carry no meaning from their spelling. Allocation MUST prevent collision/reuse in their scope, including after deletion; tombstoned identities MUST NOT identify a different object.

| Identifier | Scope, ownership and persistence |
| --- | --- |
| `device_id` | Registry-owned; unique for the registry's lifetime; persistent across address/name/provider changes |
| `target_id` | Registry-owned; unique within original device identity; persistent across binding and association changes |
| `binding_id` | Registry-owned; unique registry-wide; persistent while the same external endpoint association exists; replacement gets a new ID |
| `request_id` | Core-issued opaque ID; unique registry-wide for all user intents; a retry retains it, a new intent gets another |
| `item_id`, `asset_id`, `resource_id` | Registry-owned opaque IDs; unique within their catalog, asset store or registry respectively; persistent only for verified identity continuity |
| `operation_id`, `field_id` | Semantic names, not opaque: exact lowercase names in sections 6/7; vendor names follow section 6; meanings MUST NOT be reused |

`common_model_version = {major: UInt32, minor: UInt32, patch: UInt32, candidate: UInt32?}`; frozen v1.0.0 uses `{1,0,0}`. Candidate versions MUST match exactly and MUST NOT claim frozen compatibility. Future frozen major versions require exact major agreement and an explicitly negotiated minor/operation subset; patch MUST NOT alter observable semantics. Unknown enums MUST remain unsupported/unknown, never be coerced to a known meaning.

All revisions/generations are `UInt64`, start at 1, increase strictly in their scope and MUST NOT wrap. Exhaustion MUST stop mutation until a new identity is allocated. They compare by equality for validity; greater/less is meaningful only in the same scope. Persistent scopes MUST retain counters across restart. Historical values MUST NOT be resurrected on rollback.

| Counter | Scope and increment event |
| --- | --- |
| `capability_revision` | Target; any descriptor/support/domain/availability/authorization change |
| `mapping_revision` | Binding; any mapping contract, external version or verification change |
| `association_generation` | Device and target each have their own; any merge, reassociation or rollback affecting that identity |
| `catalog_generation` | `(device_id,target_id,catalog_kind)`; any membership, item identity, ordering or token-binding change; identical verified refresh does not increment |
| `media_context_generation` | Target; source, item or playback-session identity change, or inability to establish continuity after reconnect |
| `session_generation` | Binding; connection creation, reconnect or sequence-domain reset; persistent across restart |
| `token_generation` | Binding/catalog; change to the private item-to-external-token association |

Reference/command validity requires matching all applicable scoped counters, not merely the largest number. Capability/mapping/association changes invalidate unsent captured work. Catalog/token changes invalidate selections; media changes invalidate context-dependent work and media fields. Session changes invalidate old callbacks/observations. In-flight execution cannot be undone; its historical identity and evidence MUST be retained.

## 3. Value and time model

| Type | Exact logical domain |
| --- | --- |
| `Bool` | Only true or false; integers/strings are not booleans |
| `UInt32`, `UInt64`, `Int64` | Integers in `[0,2^32-1]`, `[0,2^64-1]`, `[-2^63,2^63-1]` respectively; fractional values are invalid |
| `Rational` | `{n:Int64,d:UInt64}`, `d>0`, reduced by greatest common divisor; zero is `{0,1}`; exact arithmetic/comparison with sufficiently wide intermediates |
| `Normalized` | Rational in `[0,1]`; volume measures a target's advertised numeric level, not loudness or dB |
| `String` | Valid UTF-8, no surrogate encodings; equality by exact Unicode scalar sequence, no normalization/case folding; max 4096 encoded bytes |
| `Enum` | Exact case-sensitive declared token; no integer alias |
| `DurationMs` | UInt64 count of elapsed milliseconds; no seconds or implicit unit conversion |
| `MonoTime` | `{clock_epoch:OpaqueId,tick_ms:UInt64}`; nondecreasing Core monotonic clock including suspended time; clock epoch is unique per restart |
| `Value<T>` | Tagged `PRESENT{value:T}` or `ABSENT{reason:UNKNOWN/UNSUPPORTED/NOT_APPLICABLE/UNAVAILABLE}` |

Clock readings of different epochs MUST NOT be compared. Addition overflow MUST be rejected, not wrap. UTC/source timestamps are diagnostic strings plus declared clock quality, never scheduling clocks. Rational reduction is canonicalization, not quantization. Decimal logical examples such as `0.68` mean exact `17/25`; a serialization MUST preserve the logical value. NaN, infinity, overflow and an unrepresentable Rational MUST be rejected. Floating-point implementations MUST NOT introduce different rounding/tie decisions.

UNKNOWN MUST NOT become false, zero or empty text. Confirmed empty text and empty catalogs are valid present values. UNAVAILABLE is not UNSUPPORTED. Playback NOT_PLAYING is not STOPPED; v1 has no generic stopped observation. Position/duration are integer milliseconds, not wall time. Read precision MUST be preserved using the descriptor, even when a value has trailing zero milliseconds.

## 4. Device, target, binding and connectivity records

`CommonDevice = {device_id, association_generation, display_name:String, device_class: AUDIO_PLAYER/TV/RECEIVER/SET_TOP_BOX/GENERIC/UNKNOWN, targets:map<target_id,Target>, bindings:map<binding_id,Binding>, connectivity:Connectivity, manufacturer?:Value<String>, model?:Value<String>, profile?:Value<AssetRef>, artwork?:Value<AssetRef>}`.

`Target = {target_id, device_id, association_generation, capability_revision, media_context_generation, display_name:String, capabilities:map<CapabilityKey,CapabilityDescriptor>, fields:map<field_id,FieldSnapshot>, resource_ids:OpaqueId[], ordering_mode:STRICT/LOCAL_ONLY}`. Empty capability/field maps are valid; every binding points to exactly one target. ordering_mode defaults to STRICT at creation; an explicitly configured LOCAL_ONLY target does not promise physical execution order. Policy changes increment capability_revision. A device merge MUST NOT merge targets or automatically union their descriptors.

`Binding = {binding_id, device_id, target_id, device_association_generation:UInt64, association_generation:UInt64, mapping_revision, session_generation, adapter_version:String, external_version:Value<String>, model_versions:Version[], authorization:AUTHORIZED/UNAUTHORIZED/BLOCKED/UNKNOWN, reachability:REACHABLE/UNREACHABLE/UNKNOWN/UNVERIFIED, mapping_evidence:Evidence[], owner_priority:UInt32, last_contact?:MonoTime, transport_refs:OpaqueId[], private_metadata_ref?:OpaqueId, credential_ref?:OpaqueId}`.

Private metadata and credential references MUST stay inside Core/adapter storage and MUST NOT appear in UI snapshots, field values or errors. Transport refs are internal; UI receives common identity, resolved capabilities and confidence only. An AssetRef is `{asset_id}` resolved through a neutral authenticated asset service, never a credential-bearing URL.

`Connectivity = {status:REACHABLE/PARTIAL/UNREACHABLE/UNVERIFIED/UNKNOWN, routes:map<binding_id,RouteConnectivity>}`; `RouteConnectivity = {reachability, authorization, last_contact?:MonoTime}`. Define usable as REACHABLE and AUTHORIZED: if every nonempty route is usable, REACHABLE; if at least one is usable, PARTIAL; otherwise if every nonempty route is UNREACHABLE, UNREACHABLE; otherwise if any is UNVERIFIED, UNVERIFIED; otherwise UNKNOWN. Empty routes yield UNKNOWN. Connectivity MUST NOT imply power state or command support.

## 5. Capability descriptors and schema definitions

`CapabilityKey = {kind:OPERATION/FIELD, id:operation_id/field_id, binding_id}`; family labels are informative only. Missing keys mean UNKNOWN, never supported. Read and write keys are independent.

`CapabilityDescriptor = {key, support:SUPPORTED/UNSUPPORTED/UNKNOWN, availability:READY/OFFLINE/UNAUTHORIZED/BLOCKED/CONTEXT_UNAVAILABLE/UNKNOWN, capability_revision, mapping_revision, evidence:Evidence[], argument_schema:Schema?, result_schema:Schema?, value_schema:Schema?, units:Unit[], numeric_mapping?:NumericMapping, required_context:ContextRequirement[], observation:AVAILABLE/UNAVAILABLE/UNKNOWN, semantic_variant:String?, idempotence:NON_IDEMPOTENT/CONTEXT_DEPENDENT/VERIFIED_IDEMPOTENT?, retry:RetryPolicy?, freshness:FreshnessPolicy?, resource_ids:OpaqueId[], execution_evidence:ExecutionContract?}`.

`Evidence = {evidence_id:OpaqueId, kind:PROJECT_DESIGN/OFFICIAL_CONTRACT/PROTOCOL_TEST/OWNER_ASSOCIATION/HARDWARE_TEST, reference:String, verified_claims:String[], version:Value<String>}`. Evidence for one claim MUST NOT verify another; project design cannot verify external support. Support UNKNOWN/UNSUPPORTED requires only key/support/availability/revisions/evidence/resources/context/observation/units; omitted optional contracts grant no guarantees. SUPPORTED requires nonempty relevant evidence and the following complete contracts:

- OPERATION: argument schema exactly restricting section 6, result schema exactly section 11, idempotence, retry, execution evidence and any applicable numeric/catalog/context guarantees. Availability READY additionally requires current authorization, identity and mapping verification. Unsupported constraints cannot be made READY.
- FIELD: value schema exactly restricting section 7, freshness and observation policy; argument/result/idempotence/retry MUST be absent. Observation UNAVAILABLE does not turn field support into unsupported.

`Schema` is a closed tagged definition: `BOOL`, `UINT32{min,max}`, `UINT64{min,max}`, `INT64{min,max}`, `RATIONAL{min,max}`, `STRING{max_bytes}`, `ENUM{values}`, `REF{kind}`, `ASSET_REF`, `RECORD{required:map<String,Schema>,optional:map<String,Schema>}`, `UNION{tag:String,variants:map<String,Schema>}`, `LIST{element:Schema,max_count:UInt32}`. Bounds MUST fit section 3, min<=max, enum sets MUST be nonempty, and recursion/cycles are forbidden. Units use the section 1 path-bearing Unit record and MUST agree with their referenced argument/result/field schema. Unknown required extension schemas invalidate support. Catalog arrays, recipe lengths and operation-argument LIST counts are bounded at 1024; discrete operation count arguments at 65535; mappings MAY narrow, never widen, these limits. These argument bounds do not truncate internal result/decision history: Attempt[] is bounded at 3072 (=1024 recipe steps * 3 attempts), ordinary requests at 3. Descriptor result-schema LIST bounds MUST cover these derived maxima; field conflict/participant arrays cover the associated registry routes/retained participants, not the argument LIST bound. Required evidence/decision state MUST NOT be dropped to fit an argument bound.

`ContextRequirement = NONE/CATALOG/MEDIA/SEEK_WINDOW/STATE_PRECONDITION`; these form an explicit set, not alternatives. `ExecutionContract = {feedback:NONE/CORRELATED_RESULT, completion_claim:String, guaranteed_no_execution_errors:String[], context_guard:VERIFIED/UNKNOWN/NOT_APPLICABLE, selection_guard:VERIFIED/UNKNOWN/NOT_APPLICABLE, ordering_fence:VERIFIED/UNKNOWN, mapping_reference:String}`. Verified means evidence supports that exact guarantee, not a protocol has an acknowledgement. Read-then-toggle set emulation is forbidden unless verified atomic/conditional or equivalent exclusive-control semantics prevent other-controller races, and relevant state is fresh/conflict-free.

## 6. Operation contracts

Every operation requires an explicit target. Empty arguments are `{}`, not null. Automatic retry is **disabled by default for every operation**. Result semantics for every row are section 11; none implies the named field changed without an observation. Context requirements in this table are mandatory minima; descriptors MAY add explicit preconditions. `N` means NON_IDEMPOTENT; `C` means CONTEXT_DEPENDENT and not replay-safe until an individual mapping verifies idempotence and section 12 permits replay. Descriptors MUST NOT classify an N operation as VERIFIED_IDEMPOTENT.

| Operation IDs | Exact arguments | Required context | Class; forbidden inference |
| --- | --- | --- | --- |
| `power.set` | `{state:ON/OFF/STANDBY}`; descriptor advertises permitted values | NONE, plus STATE_PRECONDITION for verified conditional emulation | C; toggle is not set; emission is not observed power |
| `power.toggle` | `{}` | NONE | N; unknown initial power stays unknown |
| `volume.set` | `{level:Normalized}` | NONE | C; normalized value is not dB/loudness |
| `volume.step` | `{direction:UP/DOWN,count:UInt32[1,65535]}` | NONE | N; steps cannot establish an absolute level |
| `volume.mute` | `{muted:Bool}` | NONE | C; mute is not zero level or power off |
| `playback.play`, `playback.pause`, `playback.stop` | `{}` | MEDIA | C; no toggle substitution; stop side effects require declared semantic variant; inactivity is not stopped |
| `playback.previous`, `playback.next` | `{}` | MEDIA | N; target-defined item traversal is not channel step |
| `playback.seek` | `{position_ms:DurationMs}` | MEDIA and SEEK_WINDOW | C; no relative seek, no implicit unlimited timeline |
| `playback.rewind`, `playback.fast_forward` | `{}` | MEDIA | N; one discrete action, not held key, speed parameter or invented seek delta |
| `navigation.up`, `navigation.down`, `navigation.left`, `navigation.right`, `navigation.select`, `navigation.back`, `navigation.home` | `{}` | NONE | N; one discrete action; Back is not Exit, Home is not RootMenu without verified meaning |
| `source.select` | `{source:SelectionRef<SOURCE>}` | CATALOG | C; input selection is not station/content selection |
| `channel.select` | tagged `REFERENCE{channel:SelectionRef<CHANNEL>}` or `NUMBER{major:UInt32,minor?:UInt32}` | CATALOG for REFERENCE; explicit verified number domain for NUMBER | C; absent minor is not zero; no friendly-name matching |
| `channel.step` | `{direction:UP/DOWN,count:UInt32[1,65535]}` | NONE | N; descriptor MUST declare ordering and wrap/end behavior; not media-next |
| `favorites.activate` | `{favorite:SelectionRef<FAVORITE>}` | CATALOG; recipe steps capture their own contexts | N; distinguish DEVICE_NATIVE/REMOTE_RECIPE variant; no generic scene equivalence |
| `application.launch` | `{application:SelectionRef<APPLICATION>,parameters?:Record}` | CATALOG | C; parameters MUST match the descriptor's closed schema; absent parameters is not an empty supplied record |
| `content.launch` | tagged `REFERENCE{content:SelectionRef<CONTENT>}` or `URI{uri:String,parameters?:Record}` | CATALOG for REFERENCE; explicit supported URI scheme/content/parameter domain for URI | C; not every URI is playable; launch is not an input change |
| Vendor operation | `{payload:Record}` with complete versioned closed schema | Explicit declared set | N by default; C only for documented set semantics; no opaque protocol packets |

Vendor IDs MUST use `vendor.<reverse_dns_namespace>.<operation>.v<major>` with lowercase ASCII labels separated by dots, each matching `[a-z][a-z0-9_]*`; namespace ownership and semantic major version are required. Payload semantics MUST be neutral typed values; protocol encodings belong privately to the adapter. Optional launch parameters use Schema RECORD, not arbitrary JSON.

Catalog queries `source.enumerate`, `channel.enumerate`, `favorites.enumerate`, `application.enumerate`, `content.enumerate` have `{}` arguments, no writes and no automatic retry; idempotence C, catalog context NONE. Their result is `CatalogSnapshot` in section 15, returned only from verified enumeration. They do not imply select/launch support. Query completion confirms the query result, not a physical action.

## 8. State observations and freshness

`StateObservation = {observation_id:OpaqueId, device_id, target_id, field_id, value:Value<T>, confidence:AUTHORITATIVE/REPORTED/ASSUMED/UNKNOWN, binding_id, provenance:ProvenanceHop[], device_association_generation, association_generation, mapping_revision, session_generation, receipt_time:MonoTime, acquisition_order:UInt64, origin:LIVE/CACHE_REPLAY/RESYNC, observation_time?:MonoTime, source_time?:String, age_at_receipt_ms?:DurationMs, clock_quality:BOUNDED/UNKNOWN, freshness:FreshnessPolicy, source_sequence?:Sequence, media_context_generation?:UInt64, pending_request_id?:OpaqueId}`.

`ProvenanceHop = {actor_id:OpaqueId, role:TARGET/INTERMEDIARY/ADAPTER/CORE, evidence_id:OpaqueId}`. Direct verified target samples MAY be AUTHORITATIVE; intermediary reports MUST be REPORTED unless explicitly optimistic, then ASSUMED. Emission never creates authoritative evidence. ABSENT values have confidence UNKNOWN; PRESENT values MUST NOT use UNKNOWN confidence. ASSUMED MUST be an overlay, never an observed truth candidate.

`FreshnessPolicy = {max_age_ms:DurationMs[1,60000], acquisition:VERIFIED_SEQUENCE/VERIFIED_SERIAL_SAMPLE, source_clock_contract:Value<String>}`. No policy means no supported current field. max_age is explicit per descriptor, never inherited from arrival or a global guess. The observation's policy MUST equal its captured descriptor policy. Core observation_time, if present, MUST be a defensible acquisition time at/before receipt, never automatically receipt time. age_at_receipt MUST be a verified upper bound, including uncertainty/transport/cache delay; clock_quality BOUNDED and same-epoch acquisition time may derive it. If both time-derived age and a verified age bound are supplied, use their maximum. A future acquisition time or invalid/overflow age is invalid evidence. Otherwise age is unknown.

At evaluation time t, upper-bound age is `age_at_receipt_ms + (t - receipt_time)`. FRESH iff same clock epoch, bounded age strictly less than max_age, matching current association/mapping/session/media generations and defensible causal order. Equality is STALE. Unknown-age observations are UNKNOWN_AGE, excluded from current truth and retained diagnostically. Receipt alone never makes them fresh. CACHE_REPLAY preserves original age; RESYNC needs verified acquisition, not merely its name.

`Sequence = {domain:OpaqueId,ordinal:UInt64}`. Ordinals compare only within a verified domain/session. Greater replaces; lesser is discarded; equal plus equal typed value/context is duplicate and MUST NOT rejuvenate age; equal plus different value/context invalidates that source's current field, records a source conflict and requires RESYNC. Receipt/diagnostic metadata are not the compared payload. Reset/domain change increments session and invalidates its current samples until verified RESYNC. No guessed wrap ordering.

With VERIFIED_SERIAL_SAMPLE, the adapter MUST acquire nonoverlapping verified samples and assign increasing acquisition_order; beginning a later acquisition invalidates acceptance of a reply for an earlier acquisition. Unordered unsolicited callbacks MUST NOT claim this mode. Without a verified sequencing/acquisition guarantee, observations cannot be promoted to current truth. Old-session callbacks are discarded regardless of receipt time. Reconnect increments session, marks prior samples STALE, rechecks capabilities/identity and requires verified RESYNC before readiness. Media fetches also check section 15.

## 9. Selection, conflicts and overlays

`FieldSnapshot = {selected:Value<StateObservation>, conflict_set:StateObservation[], conflict_latched:Bool, conflict_state:ConflictState, optimistic_overlay:Value<StateObservation>, history:StateObservation[]}`. `ConflictState = {revision:UInt64, participants:ConflictParticipant[]}`; revision starts at 1 and increments on participant/evidence changes, without wrap. `ConflictParticipant = {binding_id, conflict_ingress:UInt64, resync_started_ingress:Value<UInt64>, resync_observation:Value<StateObservation>, exclusion_evidence:Evidence[]}`. Core persists this decision state independently of diagnostic history; an unlatched field has an empty participant list. Participants sort by binding_id. A latch persists across restart; unavailable decision state blocks state-dependent work pending verified reconciliation.

Only the latest causally valid observation per binding enters selection. Eligible candidates are FRESH, PRESENT and non-ASSUMED. Sort AUTHORITATIVE before REPORTED, then ascending owner_priority, binding_id and observation_id. Select the first. Numeric equality is exact; references compare the full identity/generation tuple; other values use section 3. conflict_set contains all eligible candidates in this same order iff at least two values differ; otherwise it is empty. Selection never proves other reports false.

When no eligible PRESENT candidate exists, reduce absence across all current associated bindings for the field. A missing descriptor or UNKNOWN support contributes UNKNOWN; verified UNSUPPORTED contributes UNSUPPORTED. A SUPPORTED binding contributes the reason of its latest FRESH, causally valid ABSENT observation; if none, it contributes UNAVAILABLE only when its current verified descriptor explicitly reports observation UNAVAILABLE or availability OFFLINE/UNAUTHORIZED/BLOCKED/CONTEXT_UNAVAILABLE; otherwise UNKNOWN. Empty binding sets yield UNKNOWN. Reduction order: any UNKNOWN => UNKNOWN; otherwise all UNSUPPORTED => UNSUPPORTED; otherwise any UNAVAILABLE => UNAVAILABLE; otherwise NOT_APPLICABLE (all remaining supported routes explicitly evidence irrelevance). Stale/unknown-age PRESENT data alone contributes UNKNOWN, never UNSUPPORTED. No absence becomes a present value.

Fresh disagreement adds every disagreeing eligible binding to the persisted participant roster; a same-sequence inconsistent payload adds that binding and invalidates its current sample. A new conflict event means first latching, adding a participant, accepting a changed disagreeing value from a participant, or detecting a new same-sequence inconsistent payload. It resets resync evidence for all participants and records the event ingress as conflict_ingress. Refresh of unchanged conflicting values and exact duplicates do not restart the episode. Freshness expiry, disconnect, descriptor removal or binding deletion MUST NOT remove participants or clear the latch. A participant is satisfied only by its latest FRESH verified RESYNC, whose verified acquisition was started by a recorded Core ingress event strictly after conflict_ingress (resync_started_ingress), with current scope/mapping/session/media generations and defensible sequence order. Ordinary LIVE/cache data cannot satisfy it. Verified association/mapping correction may exclude an erroneous participant only with recorded evidence that specifically resolves its conflict; administrative deletion alone is insufficient.

After every relevant event/clock evaluation, Core MUST clear the latch exactly when every non-excluded participant has satisfied that rule, their values all agree, and every other eligible current candidate agrees too; at least one non-excluded participant is required. If all participants are excluded, clearing instead requires explicit verified correction evidence resolving every participant. Otherwise retain the latch, including when B expires and only A resyncs. Clearing empties the roster and invalidates pre-resync candidates from involved bindings; retained current RESYNC samples may then be selected. State-dependent emulation MUST remain blocked on absent/stale/unknown-age or latched fields.

History is diagnostic: its retention/order MAY vary and is excluded from conformance equality. It MUST NOT supply counters, conflict participants, causal watermarks, barriers or other decision state; those MUST be retained independently. selected, conflict_set, conflict_state and overlay remain conformance-visible.

Only the newest nonexpired ASSUMED overlay is exposed, ordered by Core request admission serial. It remains separate from selected/conflicts and expires at the earlier of command deadline and explicit max_age. Correlated feedback never upgrades it; a verified correlated field observation, rejection or invalidation removes it. Unknown power plus toggle MUST NOT create present power; relative steps MUST NOT manufacture absolute level. Extrapolated position is ASSUMED with the same media generation and expiry. Estimation is an explicit input policy, default disabled, never an implementation guess.

## 10. Requests, admission and dispatch

`CommandRequest = {common_model_version, request_id, admission_ticket:{clock_epoch:OpaqueId,serial:UInt64}, device_id, target_id, operation_id, arguments:Record, deadline:MonoTime, capability_revision, binding_id, mapping_revision, device_association_generation, association_generation, catalog_generation?:UInt64, token_generation?:UInt64, media_context_generation?:UInt64, seek_window_generation?:UInt64, preconditions:FieldPrecondition[], route_plan:RouteCapture[], recipe_capture?:RecipeCapture}`.

`FieldPrecondition = {field_id, observation_id, expected_value:Value<T>}`; `RouteCapture = {binding_id,mapping_revision,capability_revision,token_generation?:UInt64,execution_contract:ExecutionContract}`. Core captures required fields at admission; UI need not choose protocols. The primary route is first in route_plan and matches binding_id/mapping_revision. Alternatives have identical argument domain, precision, semantic variant, target/context guarantees and resource effects; sort compatible authorized routes by owner_priority then binding_id. Captures and route order are immutable; full-envelope equality compares exact typed scalar values, ordered lists and map entries irrespective of map serialization order.

`StepCapture = {device_id,target_id,operation_id,arguments:Record,capability_revision,binding_id,mapping_revision,device_association_generation,association_generation,catalog_generation?:UInt64,token_generation?:UInt64,media_context_generation?:UInt64,seek_window_generation?:UInt64,preconditions:FieldPrecondition[],route_plan:RouteCapture[]}`.
`RecipeCapture = {recipe_id,revision:UInt64,steps:StepCapture[],lock_keys:LockKey[]}`; it is required exactly for REMOTE_RECIPE favorites.activate and forbidden otherwise. It captures 1-1024 steps, their original arguments and all applicable section 6 context, the pinned recipe revision and the exact sorted union of section 12 lock keys. It belongs to immutable parent-envelope equality. No step has an independent version, ID, ticket or deadline: these are inherited from the parent. Outer deduplication runs once; step validation runs expiry stage 1 then stages 2-8 below with inherited version/deadline, skipping outer ticket/cache/capacity handling. Steps are one user intent, not separate requests.

The following first-failure table is total. Waiting conditions are recorded but do not short-circuit later validation/deadline/capacity failures; only a rejection or cached-result decision terminates validation. At admission each stage checks the parent then all recipe captures in step order. After handover, stages 3-7 revalidate only the proposed attempt's route and remaining recipe captures; completed prefix captures remain historical and cannot themselves reject an unsent suffix. Explicit registry revocation of any affected running-parent contract still sets invalidated under the final paragraph. Within a stage check fields in their record declaration order, references by schema-path byte order and applicable route_plan in list order. At handover a dormant fallback's transient authorization/availability cannot reject the chosen current route; any changed captured revision still invalidates the captured intent. Unknown operation IDs are diagnosed at stage 5 (arguments must still be a record of section 3 typed values at stage 2; no operation-specific schema is invented); known operations use their exact closed schema at stage 2. Error detail tokens below are stable semantic reasons; optional descriptive prose is diagnostic. Local rejection uses rejection_origin CORE.

## 11. Lifecycle and results

`CommandResult = {request_id,result_revision:UInt64,lifecycle:Lifecycle,terminal:Bool,delivery:Delivery,target_outcome:Outcome,error:Value<Error>,attempts:Attempt[],progress:Progress,deadline_elapsed:Bool,invalidated:Bool,query_result?:CatalogSnapshot,waiting_reason:Value<String>,first_terminal_time:Value<MonoTime>,closure_error:Value<Error>}`. waiting_reason is PRESENT only for blocked nonterminal scheduling. first_terminal_time is assigned exactly once when scheduling closes; closure_error captures that event's error (including ABSENT NOT_APPLICABLE) and never changes. result_revision starts at 1, increments once per event that changes visible decision state, and never wraps.

`Attempt = {attempt_index:UInt32,binding_id,mapping_revision,session_generation,dispatch_time:MonoTime,closed_time?:MonoTime,step_index?:UInt32,delivery:Delivery,target_outcome:Outcome,evidence:Evidence[],guaranteed_no_execution:Bool,resource_ids:OpaqueId[],error:Value<Error>}`. Index starts at 1 and increases across the parent. closed_time is assigned once at local attempt closure for retry timers. Attempts are never removed; append verified evidence and update their derived summary, retaining previous evidence and local errors. guaranteed_no_execution becomes true only on valid correlated proof that this attempt caused no execution at its captured target/resources AND cannot execute there later; proof of past absence alone, or a fence proving only no future execution, is insufficient for this whole-attempt flag. Per-key proof and barrier resolution are section 12. No-execution requires verified proof, never timeout inference. Execution/fence proof alone MUST NOT rewrite Attempt.delivery or its prior evidence; only separately verified delivery evidence may refine that summary, preserving all earlier evidence. Any valid execution/confirmation claim also supplies verified recipient delivery evidence, hence ACKNOWLEDGED for that attempt; otherwise it is not a valid correlated completion. Contradictory evidence is quarantined diagnostically, not used to overwrite proved execution/no-execution. An acknowledgement never by itself confirms target execution.

Delivery tokens: NOT_SENT (definitely no executable emission), PARTIALLY_SENT (known incomplete emission), SENT (complete local emission), ACKNOWLEDGED (verified recipient acknowledgement), AMBIGUOUS (unresolved extent/delivery). Outcome: CONFIRMED (whole effect/query proved), UNCONFIRMED (known local work but whole target effect unproved), UNKNOWN (possible effect/extent unresolved), REJECTED (explicit refusal with origin). These are distinct axes.

Historical delivery extent and physical-execution uncertainty are independent. AMBIGUOUS/PARTIALLY_SENT delivery may remain historical after execution uncertainty is resolved. A whole-attempt guaranteed_no_execution proof does not prove what bytes were emitted, does not reduce prior emitted counts and MUST NOT synthesize CONFIRMED progress or target state.

For the lifecycle fold, genuine unresolved extent means an unresolved requested-unit emission/execution extent on an attempt not proved incapable of past AND future execution; an unresolved declared CORRELATED_RESULT obligation is also genuine uncertainty. Known local emission under feedback NONE has no such correlated obligation: its target effect remains UNCONFIRMED, not synthetic success. Mere possibility that a known open-loop emission executed or may execute is handled by physical barriers, not by changing full acceptance/known partial failure into UNCERTAIN_OUTCOME. Historical byte uncertainty on a proved-nonexecuting attempt cannot alone force that lifecycle; keep its delivery evidence and progress lower bounds. A no-future-execution fence alone does not resolve unknown past execution or a pending correlated result.

`Progress = {total:UInt32,emitted:UInt32,confirmed:UInt32,uncertain_remaining:Bool}`, with 0<=confirmed<=emitted<=total. total is valid count, captured recipe length or 1. A pre-execution refusal with unparseable/invalid count or recipe capture uses total=1 as the refusal envelope's unit, emitted=confirmed=0; it MUST NOT pretend a malformed action was scheduled. Compound emitted/confirmed count distinct requested units/steps, not attempt/frame totals; retry does not increase total or count the same unit twice. Report only proven lower bounds for unknown extent. Aggregate delivery is deterministic:

1. Whole requested effect verified and every other attempt completed or proved no execution => ACKNOWLEDGED.
2. For aggregation ONLY, exclude historical ambiguity of a guaranteed_no_execution attempt when its same logical units/recipe step are fully covered by another complete local emission with known extent. This MUST NOT alter the excluded Attempt.delivery or evidence. No covering emission => its historical ambiguity remains in aggregate delivery.
3. Any remaining unresolved historical extent => AMBIGUOUS; otherwise known 0<emitted<total => PARTIALLY_SENT; otherwise strongest aggregation-eligible retained delivery ACKNOWLEDGED>SENT>NOT_SENT (or PARTIALLY_SENT for known incomplete single-unit emission).

Confirmed completion requires confirmed=total, no unresolved requested-unit extent/declared correlated obligation and no unresolved possible-execution attempt/barrier, including superseded attempts. Historical byte uncertainty on an independently proved-nonexecuting prior attempt is not a remaining execution obligation. Aggregate ACKNOWLEDGED requires actual completion/acknowledgement evidence; no-execution/fence proof alone supplies neither.

| Lifecycle | Delivery / outcome | terminal |
| --- | --- | --- |
| QUEUED | NOT_SENT / UNKNOWN | false; no attempt begun |
| DISPATCHED | NOT_SENT / UNKNOWN; AMBIGUOUS / UNKNOWN; PARTIALLY_SENT / UNCONFIRMED; SENT or ACKNOWLEDGED / UNCONFIRMED | false; active emission, retry wait/handover or compound continuation |
| ACCEPTED | SENT or ACKNOWLEDGED / UNCONFIRMED | false for fully emitted work awaiting verified feedback; true only when all steps/units have completed their declared local-feedback obligation |
| CONFIRMED_COMPLETED | ACKNOWLEDGED / CONFIRMED | true; whole request verified, including enumeration result |
| REJECTED | NOT_SENT, PARTIALLY_SENT, SENT, ACKNOWLEDGED or AMBIGUOUS / REJECTED | true; refusal with zero proved executed units and verified no execution for every handed-over attempt |
| FAILED | NOT_SENT / UNKNOWN; PARTIALLY_SENT, SENT or ACKNOWLEDGED / UNCONFIRMED; AMBIGUOUS / UNCONFIRMED only for retained historical delivery uncertainty with no genuine unresolved extent/correlated obligation | true; definitive failure or known incomplete execution; historical delivery need not become known |
| EXPIRED_BEFORE_SEND | NOT_SENT / UNKNOWN | true; no executable handover occurred, DEADLINE_EXPIRED |
| UNCERTAIN_OUTCOME | AMBIGUOUS / UNKNOWN; PARTIALLY_SENT, SENT or ACKNOWLEDGED / UNCONFIRMED | true; possible execution unresolved at scheduling closure |

Deterministic folding, in priority order:

1. Whole request confirmed and all attempts/barriers resolved => CONFIRMED_COMPLETED. Query result exists exactly for confirmed enumeration and matches captured scope/kind.
2. While scheduling remains open: no attempt => QUEUED; active emission, compound continuation or eligible retry wait => DISPATCHED with the derived aggregate; fully emitted work awaiting correlated feedback => nonterminal ACCEPTED. An ACCEPTED attempt that closes while eligible retry scheduling remains MUST transition to DISPATCHED/retry wait; the next handover remains DISPATCHED. Direct same-event ACCEPTED -> DISPATCHED retry handover is legal, preserving all prior attempts. Known partial ongoing emission uses DISPATCHED/PARTIALLY_SENT; ambiguous extent uses DISPATCHED/AMBIGUOUS.
3. Fully emitted work whose steps all completed their local obligation (correlated confirmation or feedback-NONE complete emission), without genuine unresolved extent/correlated obligation or verified execution failure/refusal/stop cause, closes terminal ACCEPTED/UNCONFIRMED if any unit remains target-unconfirmed. Mixed confirmed/open-loop steps follow this same rule. A STRICT open-loop barrier is allowed here and is NOT proof of success; it prevents later conflicting dispatch.
4. On a stop/failure/deadline: explicit whole-intent refusal with every handed-over attempt proved not executed => REJECTED/derived-delivery/REJECTED, even if historical local byte extent remains ambiguous (keep lower-bound progress and uncertainty); otherwise genuine unresolved extent => UNCERTAIN_OUTCOME with derived delivery (UNKNOWN for AMBIGUOUS, otherwise UNCONFIRMED for known emitted work); unresolved declared correlated target result => UNCERTAIN_OUTCOME/derived-delivery/UNCONFIRMED. Historical ambiguous delivery with verified absence of past AND future execution does not select these branches. Otherwise an explicit refusal with every handed-over attempt proved not executed => REJECTED/derived-delivery/REJECTED, retaining emitted progress; otherwise a known incomplete compound with any emitted/confirmed prefix => FAILED/derived-delivery/UNCONFIRMED, PARTIAL_EXECUTION with the underlying cause and stopping step_index. Even a wholly confirmed prefix does not confirm the missing suffix. No prefix => EXPIRED_BEFORE_SEND only for deadline with NOT_SENT and proof of no executable handover; explicit local/target refusal with proved zero execution => REJECTED; other proven failure => FAILED (NOT_SENT/UNKNOWN only for proved no emission, otherwise derived delivery/UNCONFIRMED (including historical AMBIGUOUS when genuine uncertainty is resolved)). A prior delivered attempt proven not executed retains its historical delivery and on later expiry folds FAILED/DEADLINE_EXPIRED, never fabricated NOT_SENT.

A target refusal proves zero target execution only when its contract establishes that guarantee; it MUST NOT reduce prior locally emitted progress. Refusal lacking that proof closes UNCERTAIN_OUTCOME, not REJECTED. A closed attempt with no eligible retry closes UNCERTAIN_OUTCOME immediately ONLY while genuine requested-unit emission/execution extent or an explicitly declared CORRELATED_RESULT obligation remains unresolved. This rule MUST NOT override full feedback-NONE acceptance or known incomplete compound failure when local extent is known. Full known open-loop emission closes ACCEPTED/SENT (or derived ACKNOWLEDGED)/UNCONFIRMED with no error; a known stopped partial count/recipe closes FAILED with PARTIAL_EXECUTION and its underlying cause. Physical barriers follow section 12 independently. A still-active attempt waits for evidence/deadline. No eligible retry decision may keep scheduling open indefinitely. A compound stop never resumes its suffix.

Ordinary transition closure: QUEUED may remain QUEUED or become DISPATCHED/REJECTED/FAILED/EXPIRED_BEFORE_SEND. Executable handover commits the DISPATCHED stage before any synchronous emission/reply fold; externally visible QUEUED -> ACCEPTED/CONFIRMED_COMPLETED/UNCERTAIN_OUTCOME is only this compound trace, never execution without a handover; nonterminal DISPATCHED/ACCEPTED may become DISPATCHED/ACCEPTED/CONFIRMED_COMPLETED/REJECTED/FAILED/EXPIRED_BEFORE_SEND/UNCERTAIN_OUTCOME only when the fold and delivery predicates permit it. ACCEPTED -> EXPIRED_BEFORE_SEND is impossible because its prior executable emission cannot disappear. No attempted command returns to QUEUED. Terminal scheduling NEVER reopens.

`Error = {code,detail:String,rejection_origin?:CORE/TARGET,cause?:ErrorCause,step_index?:UInt32}`; `ErrorCause = {code,detail:String,rejection_origin?:CORE/TARGET}` is nonrecursive. Closed code set: UNSUPPORTED_OPERATION, INVALID_ARGUMENT, INVALID_REFERENCE, STALE_PRECONDITION, UNAUTHORIZED, UNAVAILABLE, TIMEOUT, AMBIGUOUS_DELIVERY, DEADLINE_EXPIRED, PARTIAL_EXECUTION, REQUEST_HISTORY_EXPIRED, REQUEST_ID_MISMATCH, ORDERING_BLOCKED, CANCELLED. REJECTED/FAILED/EXPIRED_BEFORE_SEND/UNCERTAIN_OUTCOME require present error; other states require ABSENT NOT_APPLICABLE. For partial failures PARTIAL_EXECUTION wraps the exact underlying cause; for ambiguity use TIMEOUT at deadline, otherwise AMBIGUOUS_DELIVERY with any underlying cause for genuine unresolved extent/declared correlation. When execution proof removes that uncertainty without proving success or explicit refusal, the definitive FAILED fold preserves the initiating failure (and closure_error) even if aggregate delivery remains historical AMBIGUOUS; this is not a new rejection or confirmation. Invalidated in-flight single work retains its initiating cause in closure_error/attempt history even if later execution completes.

Valid correlated evidence MUST update a retained result idempotently on its processing event. Same evidence adds no revision. Evidence refers to an existing historical attempt/step and its captured identity/contract; old-session evidence may resolve that historical attempt but never current fields. Eligible terminal sources for outcome resolution are UNCERTAIN_OUTCOME, FAILED with historical possible execution, and terminal ACCEPTED with independently verified correlation despite its original feedback-NONE obligation. A new execution claim for EXPIRED_BEFORE_SEND, definitely-unsent FAILED, REJECTED with proved no execution, or an already contradicted settled attempt is invalid evidence: quarantine it, keep the result, send nothing. CONFIRMED_COMPLETED cannot become failure/refusal; extra consistent evidence may enrich its history only.

After valid late evidence, rerun the closed fold: whole request proved and every other attempt completed/proved no execution => CONFIRMED_COMPLETED/ACKNOWLEDGED; explicit whole-intent refusal with every attempt proved no execution => REJECTED with derived delivery/lower-bound progress even if local byte extent is unknown; otherwise genuine unresolved extent/declared correlated obligation => UNCERTAIN_OUTCOME; explicit whole-request refusal plus proved zero execution on every attempt => REJECTED with historical delivery/emitted progress; known halted incomplete prefix => FAILED/PARTIAL_EXECUTION; a whole fully emitted but target-unconfirmed request satisfying local obligations and without verified failure/refusal/stop cause => terminal ACCEPTED; otherwise definitive zero-execution/local failure => FAILED, retaining the underlying failure (NOT_SENT/UNKNOWN only when no emission is proved, otherwise derived delivery/UNCONFIRMED). A verified late target failure cannot be hidden by prior open-loop local success. A late confirmation of one prefix step never executes/confirms a never-sent suffix. Preserve first_terminal_time, closure_error, deadline_elapsed and all historical attempts. Late evidence MUST NOT schedule new work, retry or resume FOR THE CLOSED PARENT, extend retention or overwrite a newer current field. Releasing proved keys may unblock an independently admitted intent through its existing FIFO/validation gate; it MUST NOT create a new intent or reopen the resolved parent. A valid completion resolving its original barrier MUST release that barrier; other unresolved barriers remain.

## 12. Retry, deduplication and ordering

`RetryPolicy = {automatic:Bool,fallback_on_no_execution:Bool,max_attempts:UInt32[1,3],delay_ms:DurationMs[1,60000]}`; default {false,false,1,1}. Both flags false requires max_attempts=1. automatic=true requires individually VERIFIED_IDEMPOTENT mapping, matching context and verified replay safety. A captured equivalent fallback for N requires valid proof of no past AND no possible future execution on every relevant prior attempt. N or unverified C MUST NOT replay while any such possible execution remains unresolved, including hidden transport retries. Historical AMBIGUOUS delivery alone MUST NOT prohibit that captured fallback when the whole-attempt proofs are complete. Flags, attempt limits, timers, matching captures, equivalence, supersession, compound no-resumption, deadline and acquisition checks still apply; no permission to invent retries is added. Proof must be available in the attempt-closing/fallback-decision event before parent terminal closure; if absent when the parent closes uncertain, later proof resolves history/barriers only and MUST NOT reopen scheduling. No retry alters envelope, target, precision, context or deadline.

At the first processed event at/after checked last closed_time+delay_ms, before deadline, choose the first captured READY unused fallback when fallback_on_no_execution is true and all prior attempts prove no execution; otherwise the current route only when automatic=true and verified replay-safe. Repeat section 10 validation and acquisition. If temporarily unavailable, remain nonterminal DISPATCHED/retry wait only while a legal future attempt remains possible before deadline; decide at every subsequent relevant event. Irrecoverable invalidation, supersession, exhausted attempts or elapsed deadline closes via section 11. max_attempts counts initial plus replay/fallback per logical step. A count is one compound step; partial counts never resume/replay. Delay arithmetic overflow forbids the retry and closes with INVALID_ARGUMENT/TIMER_OVERFLOW.

Newer conflicting write admission permanently cancels older retry eligibility even if the new intent fails later; it does not cancel already executed work or bypass its barrier. All writes sharing a target or declared resource conflict; queries do not supersede writes. Admission means successful new-record registration after validation/capacity, not a malformed/refused proposal. Recipe admission is one such intent across its union. A recipe step is never a newer intent.

`LockKey` is tagged `TARGET{device_id,target_id}` or `RESOURCE{resource_id}`. Every write acquires its target plus all captured affected resources; recipes acquire the exact union over all steps. Sort TARGET before RESOURCE, then unsigned ASCII order of the component ID tuple. Bare target/resource IDs never collide across namespaces. Ordinary commands and recipes follow the same rule: QUEUED owns no keys; at the first handover gate acquire the entire union atomically or acquire nothing. No incremental hold-and-wait and no admission reservation. Among otherwise ready conflicting work, the smallest admission serial gets acquisition first; an older unavailable request does not block younger ready work unless it already has a physical barrier. Evaluate readiness ignoring competing queued reservations, then choose FIFO, so a newly queued recipe cannot reserve around older ready work. Independent keys need not wait.

A running recipe retains its union scheduling reservation between steps; its parent owns all keys, so its next step/retry does not conflict with itself. Ordinary retries may reuse their own barrier only with verified replay safety or proven no execution; another intent cannot. Queries use no write reservation but do not grant any physical ordering/freshness guarantee. On terminal/cancellation/stop, release the scheduling reservation's whole union atomically. Separately retain per-attempt physical barriers on every actual affected target/resource. Thus unexecuted suffix keys are released while a sent prefix's unresolved keys remain blocked. Reservation release MUST NOT clear a physical barrier.

`RemoteRecipe = {recipe_id,revision:UInt64,steps:{device_id,target_id,operation_id,arguments:Record}[]}`, 1-1024 steps; no queries, nested favorites or count>1. Capture/validate every step at parent admission using section 10, with required guards and immutable RecipeCapture. Before each step revalidate the remaining captures and pinned recipe revision; expiry wins. Steps inherit parent ID/ticket/deadline and have 1-based step_index. Advance only on correlated whole-step confirmation or feedback-NONE complete local emission. Declared local continuation within the parent reservation is allowed; it is not confirmation of physical ordering of one-way steps. STRICT barriers still protect later independent intents.

Any stopped/rejected, genuinely uncertain or partial logical step, revocation or newer conflicting intent stops the suffix; fold under section 11. Before logical step closure, a proven-zero-execution failed attempt may use its captured eligible fallback/retry under the same validation/timer rule; genuinely uncertain recipe-step closure always stops, never retries a recipe prefix. Historical ambiguous delivery with complete no-past/no-future-execution proof may use an otherwise eligible captured fallback BEFORE logical step/parent closure; it is not resumption of a halted prefix. Already completed physical steps and their errors survive. No automatic resumption/restart of a closed recipe, even after late resolution. To repeat anything, the owner must issue a new intent with new captures.

Full dedup cache holds at most 1024 records. At the START of every serialized input/clock event, before lookup/admission, purge ALL terminal records whose current-epoch time t is >= `purge_at = max(first_terminal_time.tick_ms+60000,deadline.tick_ms)`. Use checked wide arithmetic; if purge_at exceeds UInt64 time range, keep the record protected until epoch retirement, never wrap. Purge in ascending (purge_at,admission serial,request_id) order. Do not purge active records. At exact boundary the record is already unavailable to that event, including a duplicate/late reply. Late evidence does not change first_terminal_time/purge_at. No discretionary earlier/later eviction, and no expired record retained to affect lookup. Unexpired/active capacity exhaustion returns DEDUP_CAPACITY. This is bounded deduplication, not global exactly-once execution.

Core retains lifetime ID non-reuse metadata and current-epoch compact ID-ticket pairing tombstones separately from the 1024 full records. Paired tombstones retain identity only, not result/envelope, so after purge/capacity refusal duplicates return HISTORY_EXPIRED; a swapped ID/ticket returns ID_TICKET_PAIR. Allocation, pair registration and watermark advancement are one atomic Core transaction: a refused allocated new intent consumes its ID/ticket too; it cannot be retried as a fresh allocation. Cacheable validation refusals are retained when space exists; DEDUP_CAPACITY refusals cannot be cached. Queue-full refusal is cached if dedup space exists. New IDs/tickets are Core-issued only, not caller-forged promises; section 10 defines lookup/error precedence.

Restart changes clock epoch. Old tickets return REQUEST_HISTORY_EXPIRED/OLD_EPOCH without replay; lifetime request-ID non-reuse metadata persists. After persisting unresolved effect/correlation/barrier state, retire old-epoch full dedup records and ticket lookup tombstones; they do not consume new-epoch full-cache capacity. Historical effects remain reconcilable independently, without recreating old scheduling. Persist unresolved physical barriers and sufficient immutable correlation/context/evidence state before executable handover. Full dedup purge MUST NOT purge this independent mandatory barrier state; a valid late completion after cache purge may resolve its historical barrier but MUST NOT recreate the expired full result. If barrier decision state cannot be recovered, affected bindings/targets/resources remain blocked until verified fencing/reconciliation. Never reconstruct/replay uncertain old work. Persisted evidence can reconcile historical effects without pretending the new epoch accepts old intent scheduling.

Conflicting work waits behind unresolved physical execution. For complete terminal feedback-NONE emission, release its physical barrier exactly when its target AND every actual affected resource declare LOCAL_ONLY; physical order remains unverified. Otherwise retain until verified completion/no-further-execution or verified fence invalidates that attempt. Commit valid per-attempt completion/no-execution/fence proof and release exactly its resolved physical keys BEFORE parent-result folding; parent completion does not depend circularly on an unreleased resolved barrier. Ambiguous/incomplete attempts retain each physical barrier while possible execution NOW OR LATER on that key remains unresolved, even under LOCAL_ONLY. Valid correlated proof of no execution AND no future execution resolves that possibility on its proved keys and MUST release only those keys, before rerunning the parent fold. Verified completion/no-further-execution or a verified fence also resolves future-execution ordering only on the keys its evidence actually covers; a future-only fence MUST NOT be treated as proof of no past execution or retry safety. Keep every other unresolved key/barrier, including another attempt's barrier on the same key. Per-key resolution does not set whole-attempt guaranteed_no_execution unless every affected target/resource satisfies both past-and-future absence. Preserve historical Attempt.delivery, emitted/progress lower bounds and evidence unchanged except for appending the verified proof and derived execution/barrier state; no synthetic execution/confirmation. Terminal records stay terminal, including proof arriving after deadline, purge or restart. A STRICT target may remain permanently blocked. Timeout, reconnect, source readback, priority, administrative removal and wall-clock passage cannot clear barriers. Current resource reassociation does not remove old historical barrier keys.

## 13. Deadlines

Deadlines use Core MonoTime; checked duration conversion once at admission, strictly future and <=60000 ms away. Never compare remote monotonic clocks. At EVERY already-admitted scheduling or mutation-validation event, t>=deadline wins over invalidation/authorization/context failures: stop scheduling and fold via section 11. Definitely no executable handover and NOT_SENT => EXPIRED_BEFORE_SEND/DEADLINE_EXPIRED. Genuine unresolved requested-unit extent or an unresolved explicitly declared correlated-result obligation (section 11) => UNCERTAIN_OUTCOME/TIMEOUT; known halted partial execution, including feedback NONE, => FAILED/PARTIAL_EXECUTION with TIMEOUT cause. Merely unobserved known open-loop execution cannot select UNCERTAIN_OUTCOME; its physical barrier is retained under section 12 independently; proven delivered-but-not-executed prior attempts => FAILED/DEADLINE_EXPIRED with delivery history retained. Dispatch requires t<deadline; adapters MUST NOT begin new executable work after it. A timeout cannot prove no execution.

For every retained current-epoch record, deadline_elapsed is true iff the processed event time is >= its deadline; once true it stays true. Evaluating a retained terminal result at/after deadline MUST set that flag and increment result_revision once if it changes, but MUST NOT change its lifecycle/outcome/error, reopen scheduling, change first_terminal_time or reset retention. “Unchanged terminal result” refers to scheduling/outcome, not this derived time flag. Exact cached duplicates return the current retained result after maintenance, including its flag; they never become unsent expiry. Terminal clock maintenance occurs before new evidence/lookup within an event. Purged results are not recreated.

Late evidence obeys section 11, schedules nothing and may resolve only historical effects. Reconnect never extends deadlines. Restart abandons old unsent scheduling; old dispatched effects/barriers remain uncertain pending reconciliation.

## 14. Numeric mapping and quantization

`NumericMapping = {common_domain:{min:Rational,max:Rational},external_domain:{min:Rational,max:Rational},transfer:AFFINE/TABLE,table?:{common:Rational,external:Rational}[],representable_external:RepresentableSet,resolution_common:Rational,resolution_external:Rational,rounding:EXACT/NEAREST_TIES_UP,allowed_error:Rational,sentinels:Rational[],null_handling:ABSENT_UNKNOWN,out_of_domain:REJECT}`. `RepresentableSet` is tagged FINITE{values:Rational[]} (1-65536 strictly increasing values) or GRID{first:Rational,last:Rational,step:Rational} (positive step, first<=last, last-first an exact integer multiple of step). Both are nonempty finite sets, exclude sentinels and lie inside external domain; GRID need not be materialized. Resolution is the declared finest meaningful nonzero increment, not invented decimal precision; nonuniform sets use their minimum positive spacing, singleton sets resolution=0 and TABLE only. Common/external domains MUST be ordered; AFFINE requires both spans>0 and verified numeric-level semantics. A dB/nonlinear mapping requires an explicit verified TABLE or remains UNKNOWN. TABLE requires FINITE and lists corresponding strictly increasing pairs for every representable value; no implicit interpolation. Resolution/error bounds are nonnegative and MUST match the transfer; invalid/incomplete descriptors cannot advertise support.

AFFINE uses exact `external = e_min + (common-c_min)*(e_max-e_min)/(c_max-c_min)`. EXACT rejects if not representable. NEAREST_TIES_UP selects nearest representable external value, larger external value on ties; inverse mapping gives actual common value and absolute common error MUST be <=allowed_error. Inputs outside common domain reject INVALID_ARGUMENT before quantization; no clamping in this candidate. Null/sentinel observations become ABSENT UNKNOWN. Out-of-domain external observations are invalid evidence, not zero/clamped state. Mappings MUST not publish requested precision instead of inverse representable value.

TABLE uses only listed rows. Every common row lies within common_domain, each external row exactly equals its corresponding FINITE representable value, and rows are strictly increasing on BOTH axes (singleton permitted, both resolutions zero). For EXACT, accept only exact common-row equality. For NEAREST_TIES_UP, among listed common rows choose the smallest exact absolute common distance; ties choose the larger common value (therefore larger external value). Check common-domain inclusion first, then absolute requested-to-row common error<=allowed_error; otherwise INVALID_ARGUMENT/DOMAIN. Emit that row's external value, never interpolate. Inverse accepts only an exact listed external row and returns its common value; non-row external samples are invalid evidence even inside external_domain (sentinel/null absence takes precedence). TABLE resolution is minimum positive row spacing on each axis; a singleton quantizes only in-domain values within its allowed_error. AFFINE alone uses external-axis nearest rounding. Example rows (0->0,1->10), input 1/2, NEAREST_TIES_UP, allowed_error=1/2 => external 10, actual common 1; EXACT or allowed_error<1/2 rejects.

Normative mapping examples (not protocol claims):

- Common `[0,1]`, external integer `[0,10]`, representable 0..10, AFFINE, NEAREST_TIES_UP, allowed_error=1/20. Input 17/25 maps 6.8 ->7 and observed inverse 7/10; error 1/50. Input 13/20 maps 6.5 ->7 by ties-up. Exact policy rejects 17/25. Input 101/100 is rejected before rounding.
- External rational seconds convert exactly to ms by multiplication by 1000; require integer representability or explicit quantization. Whole-second external seek accepts only multiples of 1000 under EXACT; 1250 ms rejects. With nearest ties-up and permitted error 500 ms, 1500 ms becomes 2 s/2000 ms; observation precision is 1000 ms, not 1 ms. 1.25 s observations yield 1250 ms only if that precision is actually provided.
- `SeekWindow = {generation:UInt64,min_ms:DurationMs,max_ms:DurationMs,media_context_generation,guard:VERIFIED/UNKNOWN,evidence:Evidence[]}` with min<=max. Unknown duration plus verified window `[1000,9000]` accepts seek 4000 ms; 10000 rejects. Unknown duration and absent/unverified window yields UNAVAILABLE/NO_VERIFIED_SEEK_WINDOW. Known duration alone never proves seek support. Window changes invalidate queued captures.

## 15. Catalogs and media context

`SelectionRef<K> = {kind:K,device_id,target_id,device_association_generation,association_generation,item_id,catalog_generation}`; kinds are SOURCE/CHANNEL/FAVORITE/APPLICATION/CONTENT. `CatalogSnapshot = {kind,device_id,target_id,catalog_generation,items:{item_id,label:String,reference:SelectionRef,variant?:String}[],complete:Bool}`. Empty complete catalog is known empty; absent catalog is unknown. Incomplete enumeration MUST NOT prove absence or delete retained items. Duplicate names are allowed; duplicate item IDs are invalid.

Catalog updates MUST be verified, causally current for their captured binding session/mapping/association; stale/unordered responses cannot mutate the catalog. Catalog generation is Core-owned: serialize updates, compare their merged result with the current known catalog, and republish every reference with the resulting generation.

A complete refresh authoritatively replaces membership/order only with verified full-enumeration evidence. An incomplete refresh merges: preserve every omitted known item and the relative order of ALL already-known items; update verified metadata of included known IDs in place; append newly proved IDs sorted by unsigned ASCII item_id, irrespective of partial arrival order. Partial order never reorders retained IDs. Unproved item/token continuity remains UNKNOWN and cannot make a safe selection READY. Verified identity replacement gets a new item ID, not reuse; a positively proved deletion/replacement may remove the old ID even in incomplete data, with specific evidence (omission alone cannot). Existing items retain relative order after such explicit removals. Partial updates cannot silently certify positional token stability.

Increment catalog_generation exactly once per serialized update iff the merged known membership, ordering, item identity or a verified private token association changes. Identical state, omitted items, label-only/other nonidentity metadata updates and complete-flag changes alone do not increment. Token rebinding additionally increments its scoped token_generation. Incomplete query_result remains complete=false and contains only the returned items in deterministic merged-relative order with current generation; the separately retained known catalog preserves omitted items. A full result uses the authoritative full order. [A,B] generation 5 plus incomplete [B] with no proved changes keeps known [A,B], generation 5 and A's valid ref; adding C produces [A,B,C], generation 6, invalidating ALL old generation-5 refs. A later complete [B,A,C] increments to 7; label-only refresh does not. Every publication is atomic with generation changes, invalidation and reference rebinding; adapters cannot choose the common generation.

Changed membership/order/item identity/token invalidates prior references and publishes new ones; an identical verified refresh preserves them. Current reference-valued field observations also require matching catalog/scope generations and known item identity; invalidated references become history and current ABSENT UNKNOWN until reacquired. Dispatch MUST check scope, current generation, item existence, token generation and verified selection guard. Binding-private token rebinding is allowed only before a new request with evidence of same item continuity; this candidate never rebases queued requests across a generation change. Reused positional token for another item MUST create/invalidate identity and MUST NOT select via old ref. A verified stable token or target-side conditional/revision guarantee is necessary to advertise safe strict selection; recent reads/names cannot remove the check-to-execution race.

Media changes increment media_context_generation before new state becomes visible, atomically invalidate media/title/subtitle/artist/duration/position/artwork/content/playback samples and overlays, and reject unsent context-bound work. Asset fetch completion MUST match captured media and asset/reference identity; obsolete replies are discarded. An adapter unable to correlate item/session context MUST leave mixed fields absent/unknown rather than publish a coherent-looking snapshot. Guarded commands require verified target-side context guarantees; local generation checks alone cannot prevent a remote item change during execution.

## 16. Identity and reversible association

Physical identity requires verified shared identity assertions (issuer, assertion, verification method and evidence recorded) or explicit owner association. Same name, address, MAC-like token without verified scope, or provider metadata alone MUST NOT establish identity. Device association and target association are separate recorded transactions, each storing original IDs, affected binding ownership, evidence, previous generations and rollback information.

Association increments affected device/target generations and invalidates unsent work, references and overlays. Device merge retains original identities as association members, not aliases to arbitrary new targets. Only an explicitly verified target association shares control routes. Rollback restores original records/ownership with new higher generations, cancels affected unsent work, invalidates merged references and never forwards old captured IDs to another target. In-flight records retain original binding/target/association provenance and resource barriers; rollback MUST NOT pretend physical execution was undone. Future requests use freshly published IDs/generations. Address expiry removes reachability, not persistent device identity.

## 17. Shared resources and routing

`SharedResource = {resource_id,member_targets:{device_id,target_id}[],evidence:Evidence[],ordering_mode:STRICT/LOCAL_ONLY}`. Membership declares possible shared physical effects and serializes conflicting commands, not identity equivalence. Shared declarations MUST be verified or explicitly owner-configured; adapter mappings MUST declare affected resources. Undeclared ordering guarantees remain UNKNOWN. Resource membership changes invalidate captured work and retain barriers for prior dispatched work. The captured LockKey union is computed from immutable route/step captures and registry resource membership; the section 12 all-or-none/FIFO rule applies to every write, not only recipes.

Routing filters for captured semantic compatibility, current support, authorization and context; compatible READY routes sort by owner_priority then binding_id. Route plans and their guarantees are immutable for an intent. Strict barriers apply across adapters/transports and all resource members. A fallback requires a captured matching route and verified no past AND no possible future execution on all relevant prior attempts (section 11 guaranteed_no_execution; historical delivery ambiguity alone is not a veto), or an individually verified idempotent retry satisfying section 12; it MUST NOT change target, precision, context, channel order or set/toggle semantics. Absent verified fencing means unavailable ordered execution, not an invented transport feature.

## 18. Deterministic event processing

Core serializes registry changes, admissions, handover decisions, clock/deadline checks and normalized evidence events by monotonically increasing ingress serial (UInt64 starting at 1, no wrap; exhaustion stops processing). Every event begins with deterministic dedup purge and retained-result deadline flag maintenance, then its substantive mutation/lookup, then result/conflict folds and ready FIFO scheduling. Adapter progress/evidence is validated against captured schemas before committing. Invalid normalized evidence is quarantined with no decision-state mutation. Atomic handover checks use the preceding committed registry state and current monotonic time. At identical clock ticks, ingress serial determines processing order; a revoked-before-handover command cannot send, a revoked-after-handover command may already have executed. Adapters MUST serialize any claimed acquisition sequence consistently. This specifies decision order, not a particular scheduler or firmware implementation.
