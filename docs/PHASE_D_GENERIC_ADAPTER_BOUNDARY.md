## Derived scope and design decision

Existing `Adapter`, `Dispatch`, `AdapterSink`, Core registration/mutation APIs and `Journal` already provide the generic owner contract. Keep them. A fixed pointer-free asynchronous inbox is missing: Core Text/List copies/refcounts/allocator are owner-only and cannot simply be put into an RTOS queue or constructed on transport threads. Add a bounded ingress profile plus an owner gate, not a new model, network manager or adapter registry. Full descriptor/schema construction stays on the owner using the existing Core contract; off-owner availability/withdrawal notifications may reference a currently verified descriptor but cannot create support.

## Final boundary and ownership

`control::ingress::Boundary` is one owner-controlled route attached to an already registered Core binding; it reuses existing Adapter/Dispatch/AdapterSink/Journal, descriptors and observations. Transport workers receive only `Inbox`, an owned captured `Scope` and pointer-free `Event` values. They never receive Core, Store, Text/List, a borrowed Dispatch, HOME or LVGL. Runtime passes the actual FreeRTOS task check; the always-true default exists only inside the DEVELOPMENT_ONLY synthetic Session for host fixtures. This is an API ownership contract, not a sandbox against deliberately misusing unrelated public Core APIs.

The implemented asynchronous normalization profile is deliberately finite: identifiers 128 UTF-8 bytes, scalar string 4096, four provenance hops, clock contract 256; result reference 256, four claims of 128, version 64, error detail 256 and 17 target/resource proof keys. No truncation. Reference/asset scalars, source-time conversion, serial-sample acquisition, pending-request tags, nested errors and larger evidence require an explicit measured extension; packing rejects them. A full descriptor/schema is built and published on the owner through the existing Core API. Async AVAILABILITY/WITHDRAW reference a verified existing descriptor; they cannot invent support. No generic serialization or device wire format is introduced.

Supported events are SAMPLE, RESULT, REACHABILITY, RECONNECT, MEDIA, AVAILABILITY, WITHDRAW and SHUTDOWN. All eight slots are owned inline values, plus one persistent owner scratch event. `Event` is statically asserted trivially copyable. post copies everything before returning; later source mutation/destruction cannot change the queued value. Producers must capture scope at acquisition/notification, never at delayed consumption. The header carries Core epoch, binding, local attachment incarnation, session, mapping, device/target association, capability revision and media generation. Result inner correlation retains the original request/attempt/mapping/session; outer delivery scope must still be current. This permits explicitly correlated historical evidence without allowing an old queued delivery to become current.

Owner processing rejects wrong context, old epoch/incarnation/session/mapping/association and applicable revision/media. Normalization changes receipt to the actual Core consumption time, preserves acquisition/observation time and checked-adds queue delay to verified age. Unknown age remains unknown. Future staging time, future acquisition time and overflow are rejected. Sequence identity/order and Core freshness policy still decide eligibility: accepted storage is not necessarily fresh presentation. There is no source-clock inference or cached receipt rejuvenation.

## FIFO, overflow and lifecycle

Capacity is eight; all events use FIFO and none are coalesced. Producer post uses one atomic try-lock; contention returns BUSY and sets a sticky route fault. Full/serial exhaustion returns FULL with the same fault. Subsequent posts return CLOSED until explicit owner reattachment. No lock waiting, heap-backed queue, retry or payload pointer transfer. Diagnostic counter updates use at most four CAS attempts, conservatively saturating on contention; saturation is diagnostic only. A failed scope read simply returns false, allowing the producer to decline acquisition.

At the next owner service, sticky failure closes the route, discards queued records visibly and makes Core reachability UNREACHABLE. Lost result/lifecycle evidence cannot silently preserve READY. Historical effects/barriers remain intact. Repeated fault servicing does not repeatedly mutate Core or journal. Cleanup lock contention is retried on a later owner turn with the route already inactive. Recovery is explicit `attach` plus reconnect/verified republication/acquisition, never automatic replay. Old attachment incarnation and session remain invalid even after reopening. Local incarnation and queue tickets do not wrap; exhaustion requires a new runtime identity.

Initial attach uses the verified registered binding. Reattach advances Core session; reachable alone does not make capabilities READY or old fields fresh. Reconnect invalidates old deliveries, readiness and samples; withdrawal stays withdrawn until explicit publication. Media invalidation clears old media truth. Shutdown closes input, discards queued values and marks unavailable without deleting historical effect evidence. No inbox callback owns external memory. Before destroying a wrapper, a future adapter must stop/join producers and eliminate their borrowed Inbox handle; `shutdown` closes values but cannot terminate an unimplemented transport task. The existing Core route stores a non-owning Adapter pointer: the registered Adapter must remain alive for the Core/Store route lifetime, including shutdown and reattach. This milestone closes input and reuses that same adapter; it does not implement dynamic adapter removal/replacement. Session destruction stops producers first and destroys Core/adapter/store together without further dispatch. Destruction remains on the serialized owner. Physical reset is still the current firmware service termination mechanism; no new shutdown button/task is added.

## Existing command egress and Mock

The existing `Adapter::dispatch(const Dispatch&, AdapterSink&)` is sufficient and unchanged. Core validates immutable identity/generations, establishes ordering and journals before possible handover. Dispatch request/attempt references and sink are borrowed only during the call. A future asynchronous adapter must copy the required bounded command/identity before returning, reject insufficient capacity with explicit known-unsent evidence, never retain the sink/reference, and return later owned results via Inbox. The actual transport must verify its execution session before physical handover; no generic retry is added. Existing request duplicate and journal-refusal tests prove one execution/zero unjournaled execution. Core's internal dispatch publication queue remains the existing owner-only bounded queue, not transport ingress.

Mock registration remains on owner; subsequent capability, reachability, reconnect, media and acquisition/report mutations use Boundary. Existing dispatch publications remain on Core's dispatch sink because reentrant owner mutation is forbidden. Periodic acquisition and HOME-triggered acquisition use the same checked synchronous owner fast path to preserve Phase C's measured cost. USB-triggered acquisition and f completion traverse pack -> owned Inbox -> owner decode -> normal Core -> normal HOME snapshot. This is the same inbox available to a future producer, with owner-side synthetic record construction; a separate real host producer thread proves post uses no Core mutation/allocation.

The USB owner bridge drains at most eight FIFO records to acknowledge its exact issued ticket, rather than acknowledging a preceding unrelated event. The runtime otherwise services one external event per 50-ms turn. Existing eight USB bytes/turn, one HOME intent/turn, one-second fresh acquisition, 100-ms LVGL timer, USB driver and keys are unchanged. No new task or blocking LVGL read. USB TX/ESP_LOG may wait under backpressure, so item budgets are not a wall-clock guarantee.

Pending Mock execution checks Boundary acceptance before applying its once-only effect, in addition to existing captured-session/reachability checks. Dispatch also refuses known-unsent when the boundary is already closed/faulted. A failure after genuine handover cannot undo effects; historical evidence/barriers remain authoritative. Reconnect never executes pending old-session work. HOME remains adapter/transport ignorant; its code, facade, public API and geometry are unchanged.

## Persistence and cold-start audit

No persistence backend is added. Synthetic process-local MockJournal/Store are not a durable production journal. The frozen model already requires durable identities/counters and uncertain-effect/barrier recovery; this is a production execution gate, not an optional relaxation or a new Phase D semantic. An executable real adapter must not reuse this fresh synthetic Store as safe reboot recovery. No frozen contradiction was found.

| Playback/volume/media and media context | Historical values MAY be retained diagnostically; MUST NOT be fresh current truth merely after reset. New scope, sequence/age/context evidence and acquisition are required. |

## Defects found during Phase D and corrections

These are implementation/test-review findings, not new owner hardware failures:

- Missing off-owner ingress: synchronous Core publication uses non-atomic owning refcounts/allocator. Added inline copied records and serialized owner decode; did not put owning model objects on a transport queue.
- Delayed normalization initially used staging receipt; Core correctly rejected records received at a later tick. Set Core receipt to consume time while preserving acquisition and increasing verified age; tested equality expiry, duplicate non-rejuvenation, unknown age, future time and overflow. Core unchanged.
- Synthetic bridge initially could acknowledge the head record instead of its own submission. Inbox-issued tickets and bounded FIFO drain now acknowledge only its record. Regression includes an unrelated queued volume before v=25.
- Repeated sticky-fault service initially repeated unreachable mutations. Route activity now gates the first invalidation, with cleanup still retryable; tested unchanged revision/journal on subsequent fault turns.
- Pending synthetic effect could precede a closed/faulted report refusal. Added acceptance checks before command execution and dispatch, preserving the existing once-only marker and frozen historical-effect semantics.
- Sample reset generated a 6096-byte target pack frame. In-place value reconstruction reduces it to 112 bytes without a large stack temporary. No allocator or task-stack rewrite.
- New fixture mistakes (sequence ordinal below its manually raised watermark, and assuming 3000 ms rather than the actual 5000-ms Mock freshness) were corrected to test actual semantics. No existing assertion was weakened.
